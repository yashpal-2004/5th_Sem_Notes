From Algorithms to Real-World Protocols

1.1 The Routing Triad: Algorithm → Protocol → Cloud

In theoretical networking, routing is formulated mathematically through graph algorithms like Bellman-Ford and Dijkstra. However, practical infrastructure operates across three distinct evolutionary tiers:

  • Theoretical Algorithms: Pure mathematical formulations that compute minimum cost paths over abstract graph models $G=(V, E)$.
  • Named Routing Protocols: Distributed software implementations executed directly on physical/virtual routers (e.g., RIP, OSPF, BGP) equipped with operational knobs, metric calculations, timers, failure-detection keepalives, and finite scalability limits.
  • Cloud Console Abstractions: Modern Software-Defined Networking (SDN) environments (e.g., AWS VPC Route Tables) where dynamic peer-to-peer negotiation is hidden behind a declarative management plane where network architects declare pure traffic intent.
Universal Objective

Same fundamental job: Move packets to the correct destination subnet, executed via three very different paradigms: computed by algorithms, negotiated by distributed protocols, or declared in cloud consoles.

1.2 Warm-Up Trap: Fewer Hops ≠ Faster

A fundamental design failure in early routing was equating path distance solely with hop count (the number of intermediate routers). Consider two prospective transmission paths connecting source router $S$ to destination $D$:

Path Option Physical Medium Hop Count One-Way Latency Protocol Selection
Path A Geostationary Satellite Link 1 Hop $\sim 600\text{ ms}$ (propagation delay) RIP Chooses This (Fewer Hops)
Path B Terrestrial Optical Fiber 2 Hops $\sim 8\text{ ms}$ OSPF Chooses This (Lower Cost / Faster)
Everyday Analogy: Road Travel

Counting only hops is like choosing a road route simply because it has fewer turns, completely ignoring that the road is an unpaved gravel trail with a 15 km/h speed limit, while a 2-turn highway route lets you drive at 120 km/h.

1.3 Metric Selection Determines the Optimal Path

Routing protocol correctness is strictly bound to metric fidelity: "If the metric is wrong, the 'best' path is wrong."

When an algorithm calculates a shortest path over an erroneous or naive metric, the resulting mathematical optimum can severely degrade application throughput and latency. This severe limitation directly motivated the transition from naive distance-vector hop counters to bandwidth-aware link-state protocols.

Interior Routing (IGP): RIP vs. OSPF

2.1 The Two Worlds: Interior vs. Exterior Routing

Global networking is bifurcated into two mutually exclusive administrative domains governed by differing trust models and technical goals:

  • Interior Routing (IGP - Interior Gateway Protocols): Operates strictly within a single administrative organisation (enterprise campus, corporate intranet, university data network).
    • Core Goal: Discover the optimal, highest-performance physical path (minimize latency, maximize bandwidth).
    • Trust Model: Complete mutual trust—all routers are configured and managed by the same network administration team.
    • Standard Protocols: RIP (Routing Information Protocol), OSPF (Open Shortest Path First), IS-IS, EIGRP.
  • Exterior Routing (EGP - Exterior Gateway Protocols): Operates between disparate autonomous organisations (interconnecting ISPs, cloud providers, and global telecommunications carriers).
    • Core Goal: Enforce commercial contractual agreements and business peering policies.
    • Trust Model: Zero mutual trust—nobody fully trusts competitor networks.
    • Standard Protocol: BGP (Border Gateway Protocol).
Organising Principle

Inside your building you optimize for raw speed; between buildings you negotiate business contracts.

2.2 RIP: Distance-Vector by Counting Doors

The Routing Information Protocol (RIP) is an implementation of decentralized Bellman-Ford distance-vector routing:

  • Single Metric: Strictly hop count (each traversed router interface counts as $1$ hop). It does not evaluate link bandwidth, congestion, or latency.
  • Hop Limit & Infinity: The maximum allowable path length is 15 hops. A metric value of 16 hops denotes infinity / destination unreachable. This hard ceiling limits routing loop persistence but confines RIP strictly to small LANs.
  • Periodic Advertisement: Every 30 seconds, a router broadcasts its complete distance vector to immediate neighbors.
  • Key Trade-offs:
    • Advantages: Exceptionally simple to configure; minimal computational memory and CPU overhead.
    • Disadvantages: Exceptionally slow convergence, vulnerable to count-to-infinity routing loops, completely blind to link speeds (treats 10 Gbps fiber identical to a 56 kbps dial-up line).

2.3 OSPF: Link-State with Full Network Topography

Open Shortest Path First (OSPF) represents modern, enterprise-scale link-state routing built upon Dijkstra's algorithm:

  • Bandwidth-Based Cost Metric: Link cost is inversely proportional to link capacity: $$\text{Cost} = \frac{\text{Reference Bandwidth}}{\text{Interface Bandwidth}} = \frac{10^8\text{ bps}}{\text{Bandwidth in bps}}$$ A 100 Mbps link has cost 1; a 10 Mbps link has cost 10. Higher bandwidth guarantees lower cost.
  • Global Topology Synchronization: Rather than passing computed vectors, routers flood raw Link-State Advertisements (LSAs) across the network. Every router maintains an identical Link-State Database (LSDB)—a complete, synchronized roadmap of the entire enterprise.
  • Hierarchical Areas: Supports multi-level partitioning into Areas (with Area 0 serving as the mandatory Backbone Area). Routers only calculate detailed SPF trees within their local area, while inter-area summary routes are summarized at Area Border Routers (ABRs). This prevents SPF recalculation storms and allows OSPF to scale to hundreds of thousands of hosts.
  • Convergence: Sub-second convergence triggered instantly by link-state change notifications without periodic broadcast overhead.
Weighing Roads, Not Turns: The Cost Metric Analogy

A GPS that knows actual road speeds always beats a naive map that only counts intersections. In the slide's explicit scenario:

  • Path A: 2 hops over an unpaved gravel road → Cumulative Cost = 100 (Fewer turns, but slow and expensive).
  • Path B: 3 hops over high-speed optical fiber → Cumulative Cost = 12 ✓ (More hops, but drastically faster and lower cost).

Decision: OSPF chooses Path B because its bandwidth-derived metric reflects real link quality, whereas RIP would blindly take the slower Path A.

RIP vs. OSPF at a Glance

Property RIP OSPF
Type Distance-vector Link-state
Metric Hop count (max 15) Cost (bandwidth)
Convergence Slow Fast (flooding)
Best for Tiny networks Large enterprises
Checkpoint

Why does OSPF choose better paths? Its metric directly reflects physical link quality and available bandwidth; RIP only counts hops.

3

Exterior Routing (EGP): BGP & Autonomous Systems

Course Scope Note: BGP

Scope Note: BGP is essential to understand conceptually for global internet architecture and hybrid cloud edges, but hands-on protocol configuration is outside the scope of this course.

3.1 Autonomous Systems (AS) & Path-Vector

The global Internet does not operate as a single unified network running one massive algorithm. Instead, it is an interconnected mesh of tens of thousands of independent Autonomous Systems (AS):

  • Definition: An Autonomous System is a collection of IP subnets and routers under single administrative control that implements a uniform interior routing policy (e.g., Google AS15169, AWS AS16509, Comcast AS7922).
  • Border Gateway Protocol (BGP): The de facto exterior routing protocol that binds all independent ASes into the global Internet.
  • Path-Vector Abstraction: Instead of advertising isolated distance values, BGP advertises the entire sequence of AS Numbers (AS-PATH) required to reach a target destination prefix: $$\text{Prefix: } 198.51.100.0/24 \implies \text{AS-PATH: } [\text{AS 100} \rightarrow \text{AS 200} \rightarrow \text{AS 300}]$$
  • Inherent Loop Immunity: If an autonomous border router receives an advertisement containing its own local AS number within the AS-PATH attribute, it discards the route instantly, eliminating forwarding loops by design.
Highway Analogy

Inside a sovereign country you drive freely on internal roads (OSPF/RIP); when crossing national international borders you must stop at customs checkpoints and comply with bilateral treaties (BGP).

3.2 Policy Beats Shortest Path: Economic Routing

Unlike interior protocols that obsess over latency or physical link length, BGP route selection is dictated primarily by commercial contracts, monetary settlement, and business policy:

  • Customer Routes (Preferred): Traffic received from paying down-stream customers generates revenue. Routers assign customer routes the highest local preference.
  • Peer Routes (Secondary): Settlement-free exchange of traffic between carriers of comparable scale where traffic is exchanged mutually without billing.
  • Provider / Transit Routes (Least Preferred): Routing traffic through an upstream transit ISP costs money per gigabyte. Routers will deliberately prefer a longer 4-hop customer path over a cheaper 2-hop transit provider link to optimize financial margin.
Follow the Money, Not the Miles

The global Internet does not execute one giant Dijkstra algorithm. It executes thousands of independently negotiated commercial, political, and financial agreements.

3.3 CIDR Aggregation Callback for Global BGP Scale

Connecting back to Classless Inter-Domain Routing (CIDR, Lecture 13): with hundreds of millions of IP hosts globally, advertising every distinct $/24$ subnet across border gateways would collapse router TCAM memories. BGP relies critically on CIDR route aggregation / summarization (e.g., summarizing hundreds of contiguous $/24$ subnets into a single $/18$ or $/16$ route advertisement), keeping the global Internet routing table manageable ($\sim 950{,}000$ active routes today).

Cloud Routing: The AWS VPC Route Table Abstraction

4.1 Declarative Intent vs. Distributed Negotiation

When engineering within hyperscale cloud platforms (Amazon Web Services, Microsoft Azure, Google Cloud), engineers do not configure dynamic interior routing protocols like OSPF or RIP inside their Virtual Private Clouds (VPCs):

  • Traditional On-Premises: Distributed routers communicate through continuous broadcast handshakes. Forwarding tables emerge organically through protocol convergence.
  • Cloud Virtualization: Network engineers declare deterministic forwarding intent within a centralized web console or via Infrastructure-as-Code (Terraform, AWS CloudFormation). The hypervisor SDN substrate enforces traffic forwarding invisibly under the hood.

4.2 VPC Route Table Structure: Destination → Target

Within an AWS VPC, every route table consists of clean, declarative pairs mapping a destination CIDR block to an underlying virtual network target construct:

Destination (CIDR Block) Target Construct Forwarding Behavior
10.0.0.0/16 local Internal intra-VPC communication between subnets; automatically provisioned, non-removable.
0.0.0.0/0 igw-0a1b2c3d Default gateway sending all non-VPC Internet traffic through an attached Internet Gateway (Public Subnet).
172.16.0.0/16 vgw-9f8e7d6c Corporate on-premises traffic steered into a Virtual Private Gateway (VPN / Direct Connect).
0.0.0.0/0 nat-0412ab34 Outbound-only secure Internet access for Private Subnets lacking public IPs.
Declarative Simplicity

Configuring a VPC route table is like setting a destination into your car's GPS: you specify where you want packets delivered; you do not program each individual traffic light and intersection yourself.

4.3 Where BGP Sneaks Back In: VPN & Direct Connect

While intra-VPC routing is strictly declarative, where does dynamic routing re-enter cloud architecture?

At the Hybrid Edge! When connecting corporate data centers to AWS via Site-to-Site IPsec VPN or dedicated AWS Direct Connect physical circuits, BGP runs across the tunnel interfaces between the customer router (Customer Gateway - CGW) and AWS (Virtual Private Gateway - VGW / AWS Transit Gateway):

  • Route Propagation: An AWS route table can enable Route Propagation, allowing the VGW to dynamically learn on-premises corporate subnets via BGP and automatically inject them into the VPC route table without manual intervention.

Hands-On Bake-Off & Decision Framework

5.1 The Packet Tracer Bake-Off: Static vs. OSPF vs. Cloud

To demonstrate the practical resilience of routing architectures, three approaches are evaluated under an unexpected link failure scenario:

  1. Static Routing: Routes are manually typed into each router (ip route 10.0.2.0 255.255.255.0 192.168.1.2). When a physical trunk cable is severed, traffic enters a dead black-hole. Static routes have zero adaptability and require human intervention to remediate.
  2. OSPF Dynamic Routing: Routers exchange periodic Hello keepalives. When the cable drops, neighbor adjacency times out, Link-State Update (LSU) packets flood across redundant rings, Dijkstra recalculates the shortest path tree, and the network reconverges and heals autonomously in 1 to 2 seconds.
  3. AWS VPC Route Table: Provides static-route configuration simplicity (simple table entries) combined with cloud-managed physical multi-AZ redundancy underneath—the SDN substrate reroutes packets around hardware failures transparently without running interior protocol daemons on virtual machines.

5.3 Concept Checkpoints & Protocol Selection Scenarios

Checkpoint Questions & Answers

Q1: Which protocol runs between independent Autonomous Systems?
Answer: c) BGP (Border Gateway Protocol). RIP and OSPF are strictly interior gateway protocols, while ICMP is an error/diagnostic utility.

Q2: True or False: "In AWS you typically run OSPF inside your VPC."
Answer: False. VPCs use centralized declarative route tables configured in the cloud control plane, not peer-to-peer interior routing protocols.

Q3: Why does OSPF choose higher bandwidth paths even if hop count is higher?
Answer: OSPF metrics calculate cumulative link cost derived inversely from link speed. A 3-hop 10 Gbps fiber path has drastically lower mathematical cost than a 1-hop saturated 10 Mbps satellite link.

Protocol Selection Scenarios

  • Scenario A: Tiny branch LAN with 2 routers & 30 clients → Use Static Routes or RIP (simplicity outweighs dynamic protocol overhead).
  • Scenario B: University campus connecting 15 departmental buildings → Use OSPF (hierarchical multi-area design provides bandwidth optimization and rapid convergence).
  • Scenario C: Regional ISP peering with a Tier-1 global transit carrier → Use BGP (path-vector filtering enforces transit billing and bilateral peering policies).
  • Scenario D: Microservices communicating across private and public subnets in the cloud → Use AWS VPC Route Tables (declarative cloud routing with NAT/Internet Gateway targets).
