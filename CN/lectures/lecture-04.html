The Why of Network Devices

1.1 Why Direct Cables Do Not Scale

Suppose you want every computer in a network to be able to talk directly to every other computer, and you connect each pair with its own dedicated cable. The number of cables needed for $n$ devices grows quadratically as:

Cables = n * (n - 1) / 2
  • 3 Devices: 3 cables
  • 10 Devices: 45 cables
  • 100 Devices: 4,950 cables
  • 1,000 Devices: 499,500 cables

As the network grows, the number of cables scales with the square of devices. This makes direct cabling impossible to manage in office configurations, let alone datacenter environments.

1.2 The Centralised Pivot Idea

Instead of connecting everyone to everyone, we connect every device to exactly one central device in the middle. With this topology shift, $n$ devices require only $n$ cables. This centralized pivot is the reason networking hardware exists, and the differences between devices depend on how deep they look into packets to make decisions.

Core Networking Devices

2.1 The Hub (L1 Layer)

A hub is a Layer 1 (Physical) device. It represents the most literal interpretation of connecting everyone to one device. When a signal arrives on one port, the hub replicates it electrically and broadcasts it out of every other port. It does not understand MAC addresses or IP addresses. The main weakness of a hub is unnecessary traffic—every device must inspect and discard traffic meant for other machines, causing massive congestion as the network grows.

2.2 The Switch (L2 Layer)

A switch operates at Layer 2 (Data Link) and acts like a "hub with a memory." It learns which MAC address resides on which physical port by inspecting incoming traffic. When a frame arrives, it unicasts it directly to the destination port instead of broadcasting it. The switch eliminates unnecessary local congestion but cannot read IP addresses, meaning it cannot forward traffic to other networks.

2.3 Hub versus Switch Comparison

Feature Hub Switch
Era 1980s 1990s onward
OSI Layer Layer 1 - Physical Layer 2 - Data Link
Addressing Type None MAC addresses
Forwarding Logic Broadcast (Replicates to all ports) Unicast (Sends to destination port only)

2.5 The Router (L3 Layer)

A router operates at Layer 3 (Network). It connects different local networks and forwards packets using logical IP addressing. The router makes path-finding decisions (routing) much like a GPS maps routes across different states and roads.

2.5 The Firewall (L3/L4 Filtering)

A firewall is a network security device that monitors and filters incoming and outgoing traffic based on security rules. A basic packet-filtering firewall inspects Layer 3 IP headers (Source/Destination IP) and Layer 4 TCP/UDP headers (Source/Destination Port). It decides whether to allow or block packets, reading exactly two layers deep.

2.6 Load Balancers (L4/L7 Distribution)

A load balancer distributes incoming network traffic across multiple back-end servers to prevent any single server from becoming a performance bottleneck. Operating at Layer 4 (Transport) or Layer 7 (Application), it ensures high availability and smooth service scaling for major web platforms like Netflix and Google.

2.7 Core Devices Summary Table

Device Layer Decision Parameter
Hub L1 - Physical Nothing (Repeats electrical signals)
Switch L2 - Data Link MAC addresses (local networks)
Router L3 - Network IP addresses (routing between networks)
Firewall L3 / L4 (and above) IP addresses & Port numbers
Load Balancer L4 / L7 Distribution logic across target server pools

Network Topologies

3.1 Star Topology

In a star topology, all network devices connect to a central hub or switch. Data flows from the source device to the switch, which forwards it. The design is easy to set up and maintain, but the central switch forms a single point of failure.

3.2 Mesh Topology

In a mesh topology, every device connects directly to every other device. It offers high fault tolerance because data has many paths. However, physical cabling cost scales as $n(n-1)/2$, making it complex. Mesh structures are very useful in wireless networks (e.g. Wi-Fi mesh extensions) where there are no cables.

3.3 Hybrid Topology

A hybrid topology combines multiple topologies (such as joining star, ring, or bus segments). Real-world networks of any scale are almost always hybrids because different segments of an organization have different requirements.

3.4 Environment Selection & Trade-offs

Environment Suitable Topology Primary Reason
Small Office / LAN Star Easy installation and centralized maintenance.
Smart Home Mesh Direct wireless device-to-device paths (high fault tolerance).
Enterprise Datacenter Hybrid Combines scaling flexibility with high reliability structures.

Software-Defined Cloud Networks

4.1 The Evolutionary Shift

While traditional networking relies on physical boxes, copper cables, and manual configurations, the cloud era implements the exact same concepts via software-defined networking. None of the concepts change: a load balancer or a subnet in AWS operates identical to its physical counterpart.

  • Physical Boxes become Virtual Instances.
  • Copper Cables become Virtual Overlays.
  • Manual Wiring becomes API calls & Console clicks.

4.2 AWS Regions & Edge Caching

AWS isolates workloads across geographic clusters called Regions (e.g. Mumbai), connected by high-speed fiber backbones. Edge Locations serve as Content Delivery Network (CDN) caching endpoints physically located close to users, reducing propagation latency ($d$ in $d/s$ delay formula).

4.3 Redundancy: Availability Zones

An Availability Zone (AZ) consists of one or more isolated datacenters with redundant power, cooling, and network links. Designing applications to deploy across multiple AZs ensures they survive physical facility disasters (fire, flood, local power failure).

4.4 Virtual Private Cloud (VPC) & Subnets

A VPC is a private, logically isolated software-defined network inside the cloud. Engineers control routing, security gates, and partition IP addresses into subnets mapped to specific AZs. VPC IP addressing spaces are allocated using CIDR block notations.
