The Padlock & Plaintext Vulnerabilities

1.1 Browser Padlock Breakdown

What does the padlock icon (🔒) in your browser address bar actually mean?

  • Safe Website? ❌ No. Bad actors can buy domains and obtain secure lock icons too.
  • Encrypted Connection? ✅ Yes. Data cannot be read by middle hops.
  • Verified Identity? ✅ Yes. The site domain matches the digital certificate identity.

1.2 Plaintext Eavesdropping Risk

HTTP is plaintext by design. If you send data using regular HTTP, anyone capturing the network packets (like an attacker on public Wi-Fi or an intermediary router) can read raw logins, credentials, and message content easily.

2

HTTPS & Cryptographic Core Goals

2.1 The HTTPS Definition

HTTPS is the secure version of HTTP. It wraps standard web request traffic inside an encrypted transport layer tunnel to defend against snooping.

HTTPS = HTTP + TLS

2.2 Transition: SSL to TLS

Historically, HTTPS utilized SSL (Secure Sockets Layer). Because of security flaws discovered in SSL over time, modern web systems use **TLS** (Transport Layer Security) to encrypt client-server communication channels.

2.3 Core Goals: Confidentiality, Integrity, Authentication

Secure communications rely on three major pillars:

  • Confidentiality (Privacy): Ensures information is readable only by authorized endpoints ("No eavesdropping").
  • Integrity: Guarantees data remains unaltered and accurate during transit ("No tampering").
  • Authentication: Verifies the actual identity of the server (and sometimes the client) to stop impersonation.
3

Symmetric vs. Asymmetric Encryption

3.1 Symmetric Key Exchange Issue

Symmetric encryption uses a single shared secret key for both encryption and decryption. It is fast and efficient, but presents a massive logistical issue: **how do strangers securely share the symmetric key** on an insecure open internet without someone eavesdropping on it during exchange?

3.2 Asymmetric Public/Private Keys

Asymmetric encryption uses a mathematically linked pair: a **Public Key** (can be shared with anyone to encrypt data) and a **Private Key** (kept secure by the owner to decrypt). Anyone can encrypt a message for the server, but only the server can decrypt it.

3.3 The TLS Hybrid Key Insight

Why not use only asymmetric encryption? It is mathematically heavy and slow. TLS solves this by combining both methods:

  1. Uses **Asymmetric Encryption** initially to share a symmetric key securely.
  2. Switches immediately to **Symmetric Encryption** using that shared key for fast session communications.
4

The TLS Handshake Flow

4.1 Step 1: ClientHello

The client initiates the handshake by offering supported TLS versions, cipher suites (algorithm preferences), and a random nonce string used for session calculations.

4.2 Step 2: ServerHello + Certificate

The server responds by choosing the preferred cipher suite, sending its own random nonce, and sharing its **Digital Certificate** containing the server's public key and authority signatures.

4.3 Step 3: Certificate Authentication

The client validates the server's certificate chain through Certificate Authorities (CAs). If the signature checks pass, the client trusts the server's identity, preventing Man-in-the-Middle (MitM) attacks.

4.4 Step 4: Key Exchange & Encryption Start

Client and server compute a shared **session key** using the exchanged nonces. Once calculated, they signal the switch, and all subsequent application traffic is encrypted symmetrically.

5

Trust Chains & Cloud Deployments

5.1 Certificate Authorities & Chain of Trust

Browsers trust digital certificates because they are signed by trusted Certificate Authorities (CAs). Browsers ship pre-loaded with root certificates, validating the signature chain of intermediate CAs down to individual web endpoints.

5.2 AWS Certificate Manager (ACM) Deployment

In cloud deployments, provisioning SSL/TLS certificates manually is tedious. Services like **AWS Certificate Manager (ACM)** automate certificate issuance, validation, and renewal, attaching them directly to CloudFront CDNs or Application Load Balancers (ALBs).
