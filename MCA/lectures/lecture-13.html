MIPS32 Instruction Encoding Formats
  • R-Type (Register-Register ALU): [opcode: 6] [rs: 5] [rt: 5] [rd: 5] [shamt: 5] [funct: 6] — Used for add, sub, and, or, slt. Opcode is always 0; actual op is in funct.

  • J-Type (Unconditional Jump): [opcode: 6] [target_address: 26] — Used for j and jal. Target address shifted left 2 bits.

MIPS32 Register Conventions

1.1 The 32 Architectural Registers

MIPS32 provides 32 general-purpose 32-bit registers, numbered 0 to 31. By software convention, each register has a dedicated alias and usage contract:

Register Name Number Conventional Software Role
$zero 0 Hardwired Constant Zero (0x00000000)
$v0 – $v1 2 – 3 Function Return Values / Expression Results
$a0 – $a3 4 – 7 Function Arguments 1 through 4
$t0 – $t9 8–15, 24–25 Temporaries (Caller-Saved scratchpad)
$s0 – $s7 16 – 23 Saved Values (Callee-Saved across calls)
$gp, $sp, $fp 28, 29, 30 Global Pointer, Stack Pointer, Frame Pointer
$ra 31 Return Address (written by jal)

1.2 The Hardwired $zero (Register 0)

Register $zero always returns 0 when read, and writes to $zero are discarded. This enables concise synthesis of instructions without extra hardware opcodes:

  • move $t0, $t1 → add $t0, $t1, $zero
  • li $t0, 5 → addi $t0, $zero, 5
  • nop → sll $0, $0, 0

1.3 Argument ($a0-$a3) & Return ($v0-$v1)

When calling functions, callers place up to 4 parameters into $a0–$a3. Upon completion, the subprogram places result values into $v0 (and $v1 for 64-bit pair results).

1.4 Special Pointers: $sp, $fp, and $ra

The Stack Pointer $sp points to the top of the stack (which grows downwards in memory). $ra holds the 32-bit return instruction address captured during procedure calls.

2

Caller-Saved vs. Callee-Saved Registers

2.1 Temporary ($t0-$t9) Scratchpads

Caller-Saved ($t0–$t9): The caller function assumes $t registers may be overwritten by any called subroutine. If the caller needs a $t value after a function call, the caller must push $t onto the stack before jal and restore it afterwards.

2.2 Saved Registers ($s0-$s7) Across Calls

Callee-Saved ($s0–$s7): The called subroutine guarantees that $s registers will retain their original values when the subroutine returns. If the callee needs to use $s registers internally, it must push the old $s values onto the stack in its prologue and restore them in its epilogue.

2.3 Register Preservation Contract

Preservation Rule:
- Preserved across function call: $s0–$s7, $sp, $fp, $ra, $gp
- Not preserved (can be clobbered): $t0–$t9, $a0–$a3, $v0–$v1

2.4 Function Calling Conventions Matrix

Dividing registers into caller-saved vs callee-saved prevents unnecessary stack pushes/pops for short utility functions.

R-Type (Register ALU) Format

3.1 32-Bit Bit-Field Layout

R-Type instructions operate strictly between registers. The 32 bits are split into 6 distinct fields:

$$\begin{array}{|c|c|c|c|c|c|} \hline \text{opcode (6b)} & \text{rs (5b)} & \text{rt (5b)} & \text{rd (5b)} & \text{shamt (5b)} & \text{funct (6b)} \\ \hline 31 \dots 26 & 25 \dots 21 & 20 \dots 16 & 15 \dots 11 & 10 \dots 6 & 5 \dots 0 \\ \hline \end{array}$$

3.2 The 6-Bit Opcode & Funct Split

  • opcode (bits 31-26): Always 000000 (0) for all R-type instructions.
  • rs (bits 25-21): First source register specifier.
  • rt (bits 20-16): Second source register specifier.
  • rd (bits 15-11): Destination register specifier.
  • shamt (bits 10-6): Shift amount for bit-shift operations (0 for add/sub).
  • funct (bits 5-0): Selects the specific ALU operation (e.g. 100000 for add, 100010 for sub).

3.3 Shift Amount (shamt) Operations

Shift instructions (sll, srl) shift the contents of register rt by shamt bits, storing the result in rd (rs is set to 0).

3.4 Worked Bit Encoding Examples

Encoding assembly statement: add $t0, $s1, $s2

  • $s1 = Reg 17 (10001), $s2 = Reg 18 (10010), $t0 = Reg 8 (01000).
  • Opcode = 0 (000000), shamt = 0 (00000), funct = 32 (100000).
  • Binary: 000000 10001 10010 01000 00000 100000 → 0x02324020.

I-Type & J-Type Instruction Formats

4.1 I-Type Format (Immediate & Memory Offsets)

I-Type instructions incorporate a 16-bit constant immediate value:

$$\begin{array}{|c|c|c|c|} \hline \text{opcode (6b)} & \text{rs (5b)} & \text{rt (5b)} & \text{immediate / offset (16b)} \\ \hline 31 \dots 26 & 25 \dots 21 & 20 \dots 16 & 15 \dots 0 \\ \hline \end{array}$$

4.2 Sign-Extension & Memory Loads/Stores

For arithmetic (addi) and loads (lw), the 16-bit immediate is sign-extended to 32 bits before calculation:

$$\text{Address} = \text{Reg}[rs] + \text{SignExtend}(\text{immediate})$$

For lw $t0, 8($s0): rs = $s0, rt = $t0, immediate = 8.

4.3 J-Type Format (26-Bit Jump Target)

Unconditional jumps (j, jal) encode a 26-bit target address field:

$$\begin{array}{|c|c|} \hline \text{opcode (6b)} & \text{target address (26b)} \\ \hline 31 \dots 26 & 25 \dots 0 \\ \hline \end{array}$$

4.4 Word Alignment Shift Arithmetic

Because all MIPS instructions are 4-byte word aligned, the last 2 bits of any instruction address are always 00. The 26-bit target is shifted left by 2 bits to form a 28-bit byte offset, then combined with the top 4 bits of the Program Counter (PC[31:28]).

5

RISC-V Modular ISA Architecture

5.1 RV32I Base Integer Instruction Set

RISC-V learned from MIPS, keeping registers x0 through x31 (where x0 is hardwired to 0). RV32I provides a clean 40-instruction base integer set.

5.2 Standard Modular Extensions (M, A, F, D, C)

Unlike MIPS (where all instructions are fixed into one giant spec), RISC-V is modular:

  • RV32I: Base integer ISA
  • +M: Hardware Multiply / Divide
  • +A: Atomic Memory Synchronization
  • +F/+D: Single & Double Precision IEEE 754 Floating-Point
  • +C: Compressed 16-bit Encodings for Microcontrollers

5.3 MIPS vs RISC-V Encoding Comparison

RISC-V fixes source registers rs1 and rs2 into identical bit positions across all instruction formats (R, I, S, B, U, J), simplifying hardware decode logic even further.

5.4 Assessment Check & Exercises

Self-Assessment Check

  1. Q1: Which MIPS register is hardwired to constant 0?
    Answer: Register $zero ($0).
  2. Q2: How many bits are dedicated to the opcode field in MIPS R-type instructions?
    Answer: 6 bits (always set to 000000; the operation is specified by the 6-bit funct field).
  3. Q3: Why is the 26-bit jump target in J-type instructions shifted left by 2 bits?
    Answer: Because instructions are 4-byte word aligned, so trailing bits are always 00, effectively extending jump reach by 4x.
