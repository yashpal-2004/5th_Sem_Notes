Why Reusable Building Blocks?

1.1 The Parts Catalogue & Abstraction

No modern microprocessor is designed gate-by-gate from scratch. Instead, computer engineers work with a standardized parts catalogue of reusable digital building blocks (e.g., MUXes, decoders, adders, registers). A modern CPU containing billions of transistors is built by repeating roughly 5 core block types millions of times.

This approach introduces a fundamental shift in design thinking:

  • Abstraction Layer: Engineers think in higher-level intent like "select input channel B" rather than keeping track of "17 logic gates wired in a specific topological configuration."
  • Modularity: Complex digital systems become manageable when partitioned into well-defined components with standardized interfaces.

1.2 Verification, Reuse & Cascading Scale

The reusable block philosophy provides four critical engineering advantages:

4 Pillars of Block-Based Hardware Design
  • Abstraction: Hides low-level gate complexity behind clear control/data ports.
  • Reuse: A single verified MUX or adder design can be instantiated thousands of times across the chip layout.
  • Verification: Thoroughly test the component once; trust every instantiated copy in the design.
  • Cascading Scale: Small proven blocks naturally cascade into larger blocks (e.g., three 2:1 MUXes assemble into a 4:1 MUX; 1-bit adders cascade into 64-bit ALUs).

Multiplexers (MUX) & Universal Logic

2.1 2:1 MUX: Equation & Railway Switch Analogy

A Multiplexer (MUX) acts as a digital data selector (traffic controller). It receives multiple input channels, but a dynamic select code determines exactly which input passes through to the single output line.

2:1 MUX Specifications

Inputs: Data lines \(A\) and \(B\), Select line \(S\)
Output: \(Y\)

Formula: \(Y = \bar{S}\cdot A + S\cdot B\)

  • When \(S = 0\), \(\bar{S}=1 \implies Y = A\)
  • When \(S = 1\), \(S=1 \implies Y = B\)
Railway Switch Analogy

Imagine two incoming train tracks (\(A\) and \(B\)) converging into a single track (\(Y\)). The select signal \(S\) acts as the physical switch lever. Changing \(S\) immediately routes a different train line through—purely combinational routing with zero data storage or latency delays.

2.2 4:1 MUX & Cascading Tree Construction

When selecting among 4 input data lines (\(I_0, I_1, I_2, I_3\)), 2 select lines (\(S_1, S_0\)) are required since \(2^2 = 4\).

\(Y = \bar{S_1}\bar{S_0}I_0 + \bar{S_1}S_0 I_1 + S_1\bar{S_0}I_2 + S_1 S_0 I_3\)

Each select combination acts as an active minterm that gates exactly one corresponding data input line to output \(Y\):

  • \(S_1 S_0 = 00 \implies Y = I_0\)
  • \(S_1 S_0 = 01 \implies Y = I_1\)
  • \(S_1 S_0 = 10 \implies Y = I_2\)
  • \(S_1 S_0 = 11 \implies Y = I_3\)

Cascading Hierarchy: A 4:1 MUX can be built using a tree of three 2:1 MUXes. Two 2:1 MUXes select between pairs \((I_0, I_1)\) and \((I_2, I_3)\) using \(S_0\), and a third 2:1 MUX uses \(S_1\) to select between their outputs. This tree structure scales to 8:1, 16:1, and 64:1 MUXes.

2.3 Implementing Any Function via MUX (FPGA LUT Principle)

A remarkable property of multiplexers is that a \(2^n:1\) MUX can implement any arbitrary \(n\)-variable Boolean function without requiring algebraic minimization or extra logic gates.

The MUX Implementation Trick
  1. Connect the input variables (\(A, B\)) directly to the MUX select lines (\(S_1 = A, S_0 = B\)).
  2. Wire each data input line (\(I_0, I_1, I_2, I_3\)) to fixed voltage constants (0 or 1) based on the output required by the truth table row.

Example (XOR Function \(A \oplus B\)):
Set \(S_1=A, S_0=B\). Connect \(I_0 = 0\), \(I_1 = 1\), \(I_2 = 1\), \(I_3 = 0\). The MUX now computes \(A \oplus B\)!

This exact principle powers Lookup Tables (LUTs) inside modern FPGAs (Field Programmable Gate Arrays). An FPGA is essentially an array of programmable MUX LUTs whose inputs are reconfigured by software to emulate any custom silicon circuit.

Demultiplexers & Decoders

3.1 Demultiplexer (1:4 DEMUX) & Routing Tables

A Demultiplexer (DEMUX) performs the exact inverse operation of a MUX: it takes a single input data line (\(D\)) and routes it to one of many output lines based on a select code.

1:4 DEMUX Routing Equations

With 1 data input \(D\), 2 select lines (\(S_1, S_0\)), and 4 outputs (\(Y_0, Y_1, Y_2, Y_3\)):

  • \(Y_0 = \bar{S_1}\bar{S_0}\cdot D\)
  • \(Y_1 = \bar{S_1}S_0\cdot D\)
  • \(Y_2 = S_1\bar{S_0}\cdot D\)
  • \(Y_3 = S_1 S_0\cdot D\)

All unselected output lines remain driven at 0.

Real-World Application: A CPU writing a computation result into one specific register out of a register file uses DEMUX routing logic driven by the destination register address bits.

3.2 n-to-2ⁿ Decoders & Memory Address Activation

A Decoder converts an \(n\)-bit binary code into exactly one active high output line among \(2^n\) possible output lines.

  • A 2-to-4 Decoder takes 2 binary inputs (\(A_1, A_0\)) and asserts 1 of 4 output lines (\(Y_0, Y_1, Y_2, Y_3\)).
  • A 3-to-8 Decoder converts a 3-bit input into 1 of 8 output lines.
The Heart of Computer Addressing

Decoders form the foundation of memory chip addressing and instruction decoding. When a CPU executes LOAD R1, [0x04], a 32-bit address decoder converts the binary memory address into a single physical word-line enable signal inside the RAM chip array.

Arithmetic Adders (Half Adder & Full Adder)

4.1 Half Adder (Sum & Carry Logic)

The simplest arithmetic circuit is the Half Adder, which adds two 1-bit binary numbers (\(A\) and \(B\)) to produce a Sum bit and a Carry-out bit.

Half Adder Truth Table & Boolean Logic

Truth Table outputs:

  • \(0 + 0 \implies \text{Sum}=0, \text{Carry}=0\)
  • \(0 + 1 \implies \text{Sum}=1, \text{Carry}=0\)
  • \(1 + 0 \implies \text{Sum}=1, \text{Carry}=0\)
  • \(1 + 1 \implies \text{Sum}=0, \text{Carry}=1\) (binary 10)
\(\text{Sum} = A \oplus B\)  |  \(\text{Carry}_{\text{out}} = A \cdot B\)

Limitation: A Half Adder cannot accept an incoming carry bit from a previous digit position, restricting its use to the least significant bit (LSB).

4.2 Full Adder & Ripple-Carry Cascade

A Full Adder overcomes the Half Adder's limitation by adding three 1-bit inputs: \(A\), \(B\), and an incoming carry bit \(C_{\text{in}}\).

Full Adder Equations
\(\text{Sum} = A \oplus B \oplus C_{\text{in}}\)
\(C_{\text{out}} = A\cdot B + B\cdot C_{\text{in}} + A\cdot C_{\text{in}}\)

A Full Adder can be constructed using two Half Adders and one OR gate.

Ripple-Carry Adder: Cascading \(N\) 1-bit Full Adders in series (passing \(C_{\text{out}}\) of bit \(k\) to \(C_{\text{in}}\) of bit \(k+1\)) forms an \(N\)-bit Ripple-Carry Adder capable of 32-bit or 64-bit integer addition inside an Arithmetic Logic Unit (ALU).

Instruction Set Architecture: CISC vs. RISC

5.1 The Hardware-Software Contract

An Instruction Set Architecture (ISA) serves as the explicit contract between software compilers and CPU hardware execution engines. It defines the available instructions, register sets, addressing modes, and memory access models without revealing silicon implementation details.

5.2 CISC vs. RISC Philosophy & Trade-offs

Historically, two competing philosophies evolved for designing computer instruction sets:

CISC (Complex Instruction Set Computer)
  • Philosophy: Make hardware do more work per instruction to minimize code size and RAM usage.
  • Characteristics: Variable length instructions, hundreds of specialized instructions, direct memory-to-memory operations (e.g., MULT [addr1], [addr2]).
  • Example Architectures: x86 (Intel Core, AMD Ryzen).
  • Trade-off: Complex multi-cycle hardware decoding and higher power consumption.
RISC (Reduced Instruction Set Computer)
  • Philosophy: Keep hardware simple, fast, and uniform so every instruction executes in a single clock cycle.
  • Characteristics: Fixed 32-bit instruction length, small load-store architecture (only LOAD and STORE touch memory; operations run purely on registers).
  • Example Architectures: ARM (Apple M-series, Snapdragon), RISC-V.
  • Trade-off: Requires slightly larger binary code sizes, but enables deep pipelining, high clock speeds, and extreme power efficiency.
