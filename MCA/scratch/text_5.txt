Signed vs Unsigned Overflow
Same bits, different overflow rules — the CPU computes both flags every time.
SIGNED overflow UNSIGNED overflow
Detected by: Cin ⊕ Cout at the sign bit. Detected by: the carry-out of the MSB alone.
Means: the true result fell outside −2ⁿ⁻¹ … +2ⁿ⁻¹−1. Means: the true result exceeded 2ⁿ−1 (didn't fit).
Flag name (x86): OF (Overflow Flag). Flag name (x86): CF (Carry Flag).
Your code reads OF if it cares about signed overflow. Your code reads CF if the numbers are unsigned.
Key insight: the ALU doesn't know if YOU meant signed or unsigned. It computes both flags; your instructions
decide which matters.

Key Takeaways
Five sentences that underpin every integer a computer touches.
Bits carry no inherent meaning — a number system is a convention you apply (base 2 for machines, base 16 for readable
01
binary).
02 One hex digit maps to exactly 4 bits; two hex digits = one byte — that's the entire reason hex exists.
03 Two's complement (invert + 1) is the winner: one zero, and one adder handles both addition and subtraction.
04 In two's complement the MSB carries a NEGATIVE weight, and widening a value means sign-extending, not zero-padding.
05 Overflow is silent: it happens when two same-signed numbers produce the wrong sign, detected by Cin ⊕ Cout at the sign bit.
