The Load Enable
A register must HOLD its value across clock edges until you choose to update it.
THE PROBLEM ONE BIT'S PATH
A plain flip-flop grabs D on EVERY clock edge. But a
register should keep its value for many cycles, updating
only when told.
THE FIX — a load-enable MUX per bit:
LOAD = 1 → feed new data in.
LOAD = 0 → feed the flip-flop's OWN output back in (hold).
A 2:1 MUX on each bit's D input chooses between 'new value' and
'keep current'.
The MUX + feedback loop = a register that remembers until LOAD says
otherwise.

Ripple (Asynchronous) Counter
Each flip-flop's output clocks the next — simple, but the carry ripples.
Only FF0 sees the real clock; each next FF is clocked by the previous output — the change 'ripples' along.
⚠ The ripple delay means the count is briefly WRONG while it propagates — a
problem at high speed.

Ripple vs Synchronous
Same count sequence, very different timing behaviour.
RIPPLE (async) SYNCHRONOUS
Clocking Each FF clocks the next All FFs share one clock
Speed Slow — carry ripples through Fast — all update at once
Glitches Yes — transient wrong counts No — clean output
Complexity Simple, fewer gates Needs next-state logic
Real use Toy / low-speed dividers Everything performance-critical
Trade-off in one line: ripple is cheaper to build; synchronous is the only one safe at real clock speeds.

Two Flavours: Moore vs Mealy
The difference is simply WHERE the output comes from.
MOORE MACHINE MEALY MACHINE
Output depends on the STATE only Output depends on STATE + INPUT
The output is written inside each state circle The output is written on each transition arrow
It changes only when the state changes It can react to an input within the same cycle
Simpler to reason about, and glitch-free Often needs fewer states
May need more states to do the same job Output can glitch when the input glitches
Output appears one cycle after the input Output appears in the same cycle as the input
Rule of thumb: Moore = 'output in the circle', Mealy = 'output on the arrow'. Both compute the same things.

Key Takeaways
Five sentences — from a stored bit to a thinking machine.
01 A register is n flip-flops sharing a clock — the CPU's fastest storage; add a load-enable MUX so it holds until told to update.
02 A shift register moves bits along a chain each clock — enabling serial↔parallel conversion and free multiply/divide-by-2.
03 A counter advances by 1 each clock; synchronous (shared clock) beats ripple (chained) for speed and glitch-free counts.
04 A finite state machine — states, transitions, outputs — is the universal model; registers and counters are special cases of it.
05 FSM design is a fixed recipe: diagram → table → encode states → K-map the logic → build with a state register + gates.
