1

Why OLS is not enough

The closed-form OLS solution is exact:

θ* = (XTX)-1XTy

However, there are two major limitations:

  • Limitation 1 - Computational cost: The computational cost of directly inverting this matrix is approximately O(m3). For millions of features, the inverse becomes computationally impossible.
  • Limitation 2 - Invertibility and numerical stability: The formula works only when XTX is invertible (its determinant is non-zero). This requires columns to be linearly independent.
KEY INSIGHT: If two features are exact duplicates, or one feature is a linear combination of another, XTX becomes singular, so the inverse does not exist.

Introduction to Gradient Descent

The objective of Gradient Descent is to reach the minimum of the loss function: the parameter values at the bottom give the smallest prediction error.

  • Single-variable case: For a function f(x), the derivative f'(x) tells us the slope. If we want to decrease the function, we move in the opposite direction of the derivative.
  • Multivariable case: The gradient ∇f is the vector of all partial derivatives.
TAKEAWAY: The gradient points in the direction of steepest increase. Therefore, the negative gradient points in the direction of steepest decrease.
θnew = θold - α∇L(θold)
  • θ is the full parameter vector.
  • ∇L is the vector of all partial derivatives.
  • α is the learning rate.

Warning: All partial derivatives must be computed using the old value of θ, and all parameters must be updated simultaneously.

3

Deriving the Batch Gradient Descent update for MSE

Using the Mean Squared Error (MSE), the expanded loss function is:

L(θ) = 1/m * [ (Xθ - y)T(Xθ - y) ]

When you differentiate with respect to θ and factor it out, you get the final gradient:

∇L = (2/m) * XT(Xθ - y)

Writing the final Batch Gradient Descent Update Rule by plugging the gradient into the vector equation:

θ := θ - α * (2/m) * XT(Xθ - y)
KEY INSIGHT: Why is this called Batch Gradient Descent? Because the gradient uses the full matrix X and the full target vector y. Every training example contributes to every single update step.
4

Worked example on the NST student dataset

We are predicting exam score using two features: hours studied and attendance percentage. We start with a design matrix X and target vector y.

Steps for an epoch:

  1. Compute predictions: ŷ = Xθ
  2. Compute residual vector: Xθ - y
  3. Compute the matrix product: XT(Xθ - y)
  4. Compute the MSE gradient: ∇L = (2/m) * XT(Xθ - y)
  5. Update all parameters simultaneously: θnew = θold - α∇L

Feature scaling is essential before applying Gradient Descent. Putting features on comparable scales prevents a large-magnitude feature from dominating the gradient and makes convergence faster and more stable.

5

Epochs and the full training loop

Training a model means repeating the parameter update many times. In Batch Gradient Descent, one epoch means one complete pass through the full training dataset and one full-dataset gradient update.

Training loop:

  1. Initialize parameters (e.g. θ = 0 for convex LR loss).
  2. Choose the learning rate α and number of epochs.
  3. Predict: ŷ = Xθ
  4. Compute residuals: Xθ - y
  5. Compute gradient: ∇L = (2/m) * XT(Xθ - y)
  6. Update: θ := θ - α∇L
  7. Repeat for the chosen number of epochs.
6

Learning rate, hyperparameter tuning, and trade-offs

The learning rate α is a hyperparameter. It is chosen by us before training, not learned by gradient descent. It controls how large each step is.

  • α too small: The loss decreases, but very slowly. The model is moving in the right direction, but each step is tiny.
  • α too large: The loss may oscillate or diverge. The direction may be downhill locally, but the step is so large that the algorithm overshoots the minimum.
  • α well chosen: The loss drops quickly at first and then gradually flattens near the minimum.

To find the best α, we pick candidate values, train the model separately with each value, and track the loss on a held-out validation set.
